# 回帰テスト

リポジトリのルートから実行します。

```sh
dotnet run --project tests/Emu86.Tests -c Release
dotnet run --project tests/Emu86.Tests -c Release -- completion disk
dotnet run --project tests/Emu86.Tests -c Release -- devices decode
dotnet run --project tests/Emu86.Tests -c Release -- core state
dotnet run --project tests/Emu86.Tests -c Release -- vga
```

コンソール型テストランナーです。終了コードは成功時 0、検証失敗時 1、不明なスイート名の指定時 2 です。本体ソースのコピーではなく `ProjectReference` と `InternalsVisibleTo` を使用します。スイートは作業ディレクトリ・コンソール出力を切り替えるため、同一プロセスでは逐次実行します。

| スイート | 検証対象 |
|---|---|
| `core` | ALU・条件分岐・メモリ書込・REP・FPU の回帰と両コアの比較。全汎用レジスタの 8/16/32 ビット転送、moffs 書込のページ境界・RAM 境界・診断ログも検証。 |
| `state` | CPU 更新の遅延実行・インスタンス差し替え・一括更新順序・例外伝播、`where` ガード（`Where`）と `When`/`Unless`/`Modify`、オペランド幅選択、制御レジスタとページング/TLB の同期。 |
| `devices` | CMOS・PIC・PIT・8042・ACPI、幅付き I/O、分離前の状態・読出し・診断ログとの一致。 |
| `vga` | VGA メモリウィンドウ（両コアの通常アクセス経路、奇偶/プレーナ/チェイン 4、書き込みモード 0〜3、読み出しモード 1）、レジスタ（フリップフロップ、DAC、CRTC 保護）、テキスト/mode 12h/mode 13h の描画、V86 モード遷移（IRETD での突入、INT n の #GP 反射、V86 形式のトラップフレーム、BOP の #UD）、キーボード IRQ1 の配送、PS/2 マウス(コマンド応答・IntelliMouse・パケット・IRQ12・v9 スナップショット)、システムリセット要求、16550 UART(ループバック・KDCOM のポート検出・名前付きパイプ往復・IRQ4・v10 スナップショット)、NTLDR メニュー自動操作(手順と、再判定間隔・↓ の上限・OS メニューのタイムアウト)。 |
| `decode` | 16/32 ビット ModRM と全 SIB、符号付き変位、アドレス/セグメントプレフィックス、両コアの LEA、ページ境界・BIOS エイリアス・取得失敗時の CPU 復元、命令バイト列のパーサ（プレフィックスの畳み込み、ModRM/SIB/変位の構造と実効アドレス、コンビネータの失敗時の位置、クエリ構文での合成、16 ビット IP の折り返し）と割り当て量（デコード・パーサ・高速コアの 1 命令がいずれも 0 バイト）。 |
| `snapshot` | 命令失敗時の CPU 復元、REP 再開、v2〜v7 の読込、ディスク・デバイス・VGA の復元、v10 形式のバイト列の固定（全フィールドに値を入れた状態の長さと SHA-256、復元→再保存の一致、ファイル全体のハッシュ）、フォルトの統一経路（IRETD の #GP が例外として命令開始時の状態へ戻ること、`Raise` による #GP/#PF の配送フレームと CR2、`Fault` の表記と IDT 判定）。 |
| `runner` | CLI オプション（値・既定値・エラーメッセージ・後勝ち・`--help` の一覧）、再開・停止、診断出力、環境生成とディスク解放、割り込み線の選択（優先順・IF・PIC のマスクと in-service・IDT の準備）。 |
| `completion` | ページフォルト後の上限・定期保存、完了トレース、予算消化済みでの開始、配送失敗。 |
| `disk` | BAT 計算、小容量ディスク、ペイロード・チャンク・BAT 領域境界、再オープン、親データ保持、不正な領域。 |

## 比較データ

`TestData/runner-golden.json` は今回の上限・BAT 修正前に、旧ランナーとの一致も確認して採取した 12 ケースの命令数・状態・診断・トレースの SHA-256 です。PCI に VGA デバイスを追加した 2026-10-09 に状態のハッシュだけを採り直しています（命令数・診断・トレースは不変で、差は保存される PCI コンフィグ空間のみ）。対象は通常実行・停止条件・配送できない例外で、今回修正した成功するページフォルト配送は `CompletionTests` の明示的な期待値で検証します。テキストは改行を LF に揃え、数値書式は `InvariantCulture` を使います。期待値をテスト実行時に自動更新しないでください。

`CoreTests` は前回の ALU 整理前に採取した 4,129 ケースのハッシュも照合します。両コアが同時に変わった場合も差分を検出するためのものです。

`StateTests` と汎用レジスタ転送の追加ケースは、状態操作の簡素化前にも実行して動作を確認しています。命令定義の LINQ、公開 API、CLI、保存形式は維持し、基本状態操作の多段委譲と幅選択用の一時配列を減らしています。moffs 書込は共通メモリ書込処理を使い、ログ有無・ページフォルト前に完了した部分書込を確認します。

`DeviceTests` の固定ハッシュはデバイス分離前の実装で採取し、PCI に VGA デバイス（00:02.0）を追加した 2026-10-09 に採り直しました（変わったのは保存される PCI コンフィグ空間だけで、ポート入出力の値は同じです）。0〜255 の値を各ポートへ 8/16/32 ビット幅で書き読みし、途中の保存状態と最終的な RAM/IO/CMOS/PIT 状態・診断ログも含めて比較します。従来の `EmuEnvironment` のデバイス状態フィールドは転送プロパティになっています。スナップショット形式は v10（デバイス状態の後ろに VGA・マウス・UART の状態を追加）で、v2〜v7 の読み込みも検証します。固定ハッシュが対象とする区間（ポート入出力・デバイス状態・RAM/IO）は v7 と同じです。

`DecodeTests` は期待する実効アドレスを独立に計算します。16 ビットアドレッシングではレジスタ和と変位の加算を 16 ビットで折り返します（2026-10-10 に両コアを修正。NTDETECT の `[bp - 0xae]` が別の場所へ書かれ、KDCOM が壊れた資源リストを読んでいました）。16 ビット変位は 2 バイトだけ取得し、次のページを余分に読まないことも確認します。割り当て量の表示は、ウォームアップ済みのキャッシュしたデコード State と即値 State を 10,000 回実行する限定的な計測です。今回の変更前は 1 回 2,064 バイト、変更後は 0 バイトでした。命令全体や OS ブートの速度を示すベンチマークではなく、割り当て量を合否条件にはしていません。

## テスト用ファイル

BIOS や実ディスクは不要です。`TestDirectory` がテスト実行ファイルの配置先の `test-runs/<GUID>` にファイルを隔離し、元の作業ディレクトリに戻してから、その専用ディレクトリだけを削除します。スナップショットの CLI テストは既定の 256 MB RAM を使用します。

`VhdxFixture` は読み込みに必要なヘッダ・メタデータ・BAT と末尾のペイロードを持つ最小限の人工イメージです。BAT の期待値は本体の `VhdxBatLayout` を使わずに作成します。仮想容量が大きくてもディスク全体を物理的に確保しません。これはエミュレータの回帰用で、他の VHDX ツールとの完全な互換性を検証するイメージではありません。
