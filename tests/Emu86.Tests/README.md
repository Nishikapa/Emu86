# 回帰テスト

リポジトリのルートから実行します。

```sh
dotnet run --project tests/Emu86.Tests -c Release
dotnet run --project tests/Emu86.Tests -c Release -- completion disk
dotnet run --project tests/Emu86.Tests -c Release -- devices decode
```

コンソール型テストランナーです。終了コードは成功時 0、検証失敗時 1、不明なスイート名の指定時 2 です。本体ソースのコピーではなく `ProjectReference` と `InternalsVisibleTo` を使用します。スイートは作業ディレクトリ・コンソール出力を切り替えるため、同一プロセスでは逐次実行します。

| スイート | 検証対象 |
|---|---|
| `core` | ALU・条件分岐・メモリ書込・REP・FPU の回帰と両コアの比較。 |
| `devices` | CMOS・PIC・PIT・8042・ACPI、幅付き I/O、分離前の状態・読出し・診断ログとの一致。 |
| `decode` | 16/32 ビット ModRM と全 SIB、符号付き変位、アドレス/セグメントプレフィックス、両コアの LEA、ページ境界・BIOS エイリアス・取得失敗時の CPU 復元。 |
| `snapshot` | 命令失敗時の CPU 復元、REP 再開、v2〜v7 の読込、ディスクとデバイスの復元。 |
| `runner` | CLI オプション・再開・停止、診断出力、環境生成とディスク解放。 |
| `completion` | ページフォルト後の上限・定期保存、完了トレース、予算消化済みでの開始、配送失敗。 |
| `disk` | BAT 計算、小容量ディスク、ペイロード・チャンク・BAT 領域境界、再オープン、親データ保持、不正な領域。 |

## 比較データ

`TestData/runner-golden.json` は今回の上限・BAT 修正前に、旧ランナーとの一致も確認して採取した 12 ケースの命令数・状態・診断・トレースの SHA-256 です。対象は通常実行・停止条件・配送できない例外で、今回修正した成功するページフォルト配送は `CompletionTests` の明示的な期待値で検証します。テキストは改行を LF に揃え、数値書式は `InvariantCulture` を使います。期待値をテスト実行時に自動更新しないでください。

`CoreTests` は前回の ALU 整理前に採取した 4,129 ケースのハッシュも照合します。両コアが同時に変わった場合も差分を検出するためのものです。

`DeviceTests` の固定ハッシュはデバイス分離前の実装で採取しました。0〜255 の値を各ポートへ 8/16/32 ビット幅で書き読みし、途中の保存状態と最終的な RAM/IO/CMOS/PIT 状態・診断ログも含めて比較します。従来の `EmuEnvironment` のデバイス状態フィールドは転送プロパティになっていますが、スナップショット形式は v7 のままで v2〜v6 の読み込みも検証します。

`DecodeTests` は期待する実効アドレスを独立に計算します。16 ビット変位は 2 バイトだけ取得し、次のページを余分に読まないことも確認します。割り当て量の表示は、ウォームアップ済みのキャッシュしたデコード State と即値 State を 10,000 回実行する限定的な計測です。今回の変更前は 1 回 2,064 バイト、変更後は 0 バイトでした。命令全体や OS ブートの速度を示すベンチマークではなく、割り当て量を合否条件にはしていません。

## テスト用ファイル

BIOS や実ディスクは不要です。`TestDirectory` がテスト実行ファイルの配置先の `test-runs/<GUID>` にファイルを隔離し、元の作業ディレクトリに戻してから、その専用ディレクトリだけを削除します。スナップショットの CLI テストは既定の 256 MB RAM を使用します。

`VhdxFixture` は読み込みに必要なヘッダ・メタデータ・BAT と末尾のペイロードを持つ最小限の人工イメージです。BAT の期待値は本体の `VhdxBatLayout` を使わずに作成します。仮想容量が大きくてもディスク全体を物理的に確保しません。これはエミュレータの回帰用で、他の VHDX ツールとの完全な互換性を検証するイメージではありません。
