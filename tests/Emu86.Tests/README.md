# 回帰テスト

リポジトリのルートから実行します。

```sh
dotnet run --project tests/Emu86.Tests -c Release
dotnet run --project tests/Emu86.Tests -c Release -- completion disk
dotnet run --project tests/Emu86.Tests -c Release -- core/fpu vga/palette   # ケース単位
dotnet run --project tests/Emu86.Tests -c Release -- --list                 # スイート/ケースの一覧
```

コンソール型テストランナーです。各スイートは名前付きのケースの列（`Cases`）で、引数にはスイート名（`core`）かケース名（`core/fpu`）を指定します。ケースが失敗しても同じスイートの残りのケースは実行し、`FAIL スイート/ケース: 例外` を stderr に出してから `PASS スイート (ケース数, 検証数)` か `FAIL スイート (失敗数 of ケース数)` を出します。終了コードは成功時 0、検証失敗時 1、不明な名前の指定時 2 です。検証は共通の `Assert.Equal`/`Assert.Throws`（`Assert.cs`）で、失敗は例外になります。本体ソースのコピーではなく `ProjectReference` と `InternalsVisibleTo` を使用します。スイートは作業ディレクトリ・コンソール出力を切り替えるため、同一プロセスでは逐次実行し、作業ディレクトリはスイートごとに作り直します。

ケースは原則として単独でも実行できますが、`core/baseline` は ALU とメモリ書き込みの全ケースを流してハッシュを採る 1 つのケースで、`runner/golden` と `runner/golden-plain` は同じ 12 ケースを既定の翻訳ブロックと `--no-translate` で走らせます。

## 比較データ

`TestData/runner-golden.json` は今回の上限・BAT 修正前に、旧ランナーとの一致も確認して採取した 12 ケースの命令数・状態・診断・トレースの SHA-256 です。PCI に VGA デバイスを追加した 2026-10-09 と、RTC を追加した 2026-10-28 に状態のハッシュだけを採り直し、高速コアを削除した 2026-10-31 には診断出力のハッシュだけを採り直しています（`fast-path coverage` 行の数が「IR で実行した命令数」になった分。命令数・状態・トレースは不変）（命令数・診断・トレースは不変で、差は保存される PCI コンフィグ空間と CMOS の時計・状態レジスタの初期値のみ）。対象は通常実行・停止条件・配送できない例外で、今回修正した成功するページフォルト配送は `CompletionTests` の明示的な期待値で検証します。テキストは改行を LF に揃え、数値書式は `InvariantCulture` を使います。期待値をテスト実行時に自動更新しないでください。採り直すときは `EMU86_GOLDEN_RECORD=<絶対パス>` を付けて `runner/golden runner/golden-plain` を実行すると、照合の代わりに実測値（既定と `--no-translate` の 2 回分）が 1 行ずつ JSON で記録されるので、差分を確認してから json を更新します。

`CoreTests` は前回の ALU 整理前に採取した 4,129 ケースのハッシュも照合します。通常コアと IR が同時に変わった場合も差分を検出するためのものです。

`StateTests` と汎用レジスタ転送の追加ケースは、状態操作の簡素化前にも実行して動作を確認しています。命令定義の LINQ、公開 API、CLI、保存形式は維持し、基本状態操作の多段委譲と幅選択用の一時配列を減らしています。moffs 書込は共通メモリ書込処理を使い、ログ有無・ページフォルト前に完了した部分書込を確認します。

`DeviceTests` の固定ハッシュはデバイス分離前の実装で採取し、PCI に VGA デバイス（00:02.0）を追加した 2026-10-09 に採り直しました（変わったのは保存される PCI コンフィグ空間だけで、ポート入出力の値は同じです）。RTC を追加した 2026-10-28 にも採り直しています（CMOS のインデックス 0〜9・0x0A〜0x0D・0x32 の読み出しが時計と状態レジスタになり、時刻レジスタへの書き込みが時計合わせになった分）。0〜255 の値を各ポートへ 8/16/32 ビット幅で書き読みし、途中の保存状態と最終的な RAM/IO/CMOS/PIT 状態・診断ログも含めて比較します。従来の `EmuEnvironment` のデバイス状態フィールドは転送プロパティになっています。スナップショット形式は v10（デバイス状態の後ろに VGA・マウス・UART の状態を追加）で、v2〜v7 の読み込みも検証します。固定ハッシュが対象とする区間（ポート入出力・デバイス状態・RAM/IO）は v7 と同じです。

`DecodeTests` は期待する実効アドレスを独立に計算します。16 ビットアドレッシングではレジスタ和と変位の加算を 16 ビットで折り返します（2026-10-10 に両コアを修正。NTDETECT の `[bp - 0xae]` が別の場所へ書かれ、KDCOM が壊れた資源リストを読んでいました）。16 ビット変位は 2 バイトだけ取得し、次のページを余分に読まないことも確認します。割り当て量の表示は、ウォームアップ済みのキャッシュしたデコード State と即値 State を 10,000 回実行する限定的な計測です。今回の変更前は 1 回 2,064 バイト、変更後は 0 バイトでした。命令全体や OS ブートの速度を示すベンチマークではなく、割り当て量を合否条件にはしていません。

## テスト用ファイル

BIOS や実ディスクは不要です。`TestDirectory` がテスト実行ファイルの配置先の `test-runs/<GUID>` にファイルを隔離し、元の作業ディレクトリに戻してから、その専用ディレクトリだけを削除します。スナップショットの CLI テストは既定の 256 MB RAM を使用します。

`VhdxFixture` は読み込みに必要なヘッダ・メタデータ・BAT と末尾のペイロードを持つ最小限の人工イメージです。BAT の期待値は本体の `VhdxBatLayout` を使わずに作成します。仮想容量が大きくてもディスク全体を物理的に確保しません。これはエミュレータの回帰用で、他の VHDX ツールとの完全な互換性を検証するイメージではありません。
